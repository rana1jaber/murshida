# أرشديني · Guide me

موقع تكتب فيه طالبات المدرسة أسئلتهن للمرشدة بسرية تامة، والمرشدة ترد عليهن.

- الطالبة تسجّل باسم مستعار وكلمة مرور فقط (بدون إيميل ولا جوال).
- المرشدة تشوف نص السؤال وتاريخه فقط، ولا تقدر تعرف صاحبته.
- لا يوجد استرجاع لكلمة مرور الطالبة، وهذا مذكور بوضوح وقت التسجيل.

## الملفات

| الملف | الوصف |
|---|---|
| `index.html` | الصفحة الرئيسية + إنشاء حساب + تسجيل دخول + صفحة "أسئلتي" |
| `counselor.html` | لوحة المرشدة (رابط منفصل، غير موجود في القائمة) |
| `styles.css` | التصميم المشترك |
| `config.js` | بيانات Supabase |
| `api.js` | التعامل مع Supabase (أو الوضع التجريبي) |
| `i18n.js` | النصوص بالعربي والإنجليزي، وزر الوضع الفاتح والداكن |
| `schema.sql` | الجداول وقواعد الأمان |
| `assets/hero.webp` | صورة الواجهة |
| `assets/logo.svg` | الشعار (وأيقونة التبويب) |

لإضافة نص جديد أو تعديل ترجمة: عدّلي القاموس في `i18n.js`، وكل نص في الصفحة مربوط بمفتاح عن طريق `data-i18n`.

## الوضع التجريبي

إذا كان `config.js` فارغًا، الموقع يشتغل مباشرة بدون Supabase، والبيانات تنحفظ في المتصفح فقط.
دخول المرشدة التجريبي: `counselor@demo.local` / `demo1234`.
هذا للمعاينة فقط وما يصلح للاستخدام الحقيقي.

## التشغيل الحقيقي

### 1. أنشئي مشروع Supabase
من [supabase.com](https://supabase.com) أنشئي مشروعًا جديدًا.

### 2. أنشئي قاعدة البيانات
افتحي **SQL Editor** والصقي محتوى `schema.sql` واضغطي **Run**.

### 3. إعدادات تسجيل الدخول
من **Authentication → Sign In / Providers → Email**:
- خلّي **Enable Email provider** شغال.
- **أطفئي Confirm email**، لأن إيميلات الطالبات وهمية.
- خلّي أقل طول لكلمة المرور 8.

### 4. حساب المرشدة
- **Authentication → Users → Add user**، بإيميل المرشدة الحقيقي وكلمة مرور قوية.
- ارجعي لـ SQL Editor وشغّلي (بعد تغيير الإيميل):
  ```sql
  insert into public.counselors (user_id)
  select id from auth.users where email = 'counselor@school.edu.sa';
  ```
- يُفضّل تفعيل التحقق بخطوتين (MFA) لحساب المرشدة.

### 5. اربطي الموقع
من **Project Settings → API** انسخي `Project URL` و `anon public key` وحطيهم في `config.js`.
المفتاح العام آمن في الواجهة لأن الحماية كلها في قواعد RLS. **لا تحطين أبدًا مفتاح `service_role`.**

### 6. ارفعي الموقع
اسحبي المجلد كامل على [Netlify Drop](https://app.netlify.com/drop) أو ارفعيه على GitHub واربطيه بـ Vercel.
لوحة المرشدة تكون على: `your-site.netlify.app/counselor.html`.

## كيف تتحقق السرية؟

1. **لا بيانات تعريفية:** اسم المستخدم يتحول داخليًا إلى إيميل وهمي مثل `moon_light@students.murshida.local`، ولا يُرسل له أي بريد.
2. **عمود `user_id` محجوب:** صلاحيات الأعمدة في `schema.sql` تمنع أي أحد (حتى المرشدة) من قراءته عبر الموقع. قواعد RLS تستخدمه داخليًا فقط.
3. **المرشدة ما تقدر توصل لجدول المستخدمين** (`auth.users`)، فما تقدر تربط السؤال باسم المستخدم.
4. **الجلسة تنتهي بإغلاق التبويب** (`sessionStorage`)، عشان لو الطالبة استخدمت جهازًا مشتركًا في المدرسة.
5. **لا Google Analytics ولا أي تتبع**، و `no-referrer` مفعّل.

> ملاحظة: صاحب مشروع Supabase (أنتِ أو المدرسة) يقدر تقنيًا يدخل لوحة Supabase ويشوف كل الجداول. السرية هنا تعني إن الطالبة تكتب باسم مستعار، فحتى مع الوصول الكامل ما يظهر اسمها الحقيقي.

## ملاحظات

- إذا رفض Supabase نطاق الإيميل الوهمي، غيّري `USERNAME_DOMAIN` في `config.js` لنطاق بصيغة عادية مثل `students.yourschool.com`.
- أسماء المستخدمين بالإنجليزي فقط (حروف صغيرة وأرقام و `_`)، لأنها تتحول لإيميل.
- خذي موافقة إدارة المدرسة قبل إطلاق الموقع.
